# NCDAI 2.0 implementation contract

Working scope: clinician-supervised adult NCD decision support across cardiovascular disease/hypertension, diabetes, chronic respiratory disease, CKD and cancer warning signs/referral. Cancer therapy and complex specialist treatment are outside the first release. Synthetic demonstration data only until independent clinical approval and deployment authorization. No autonomous diagnosis, prescribing or emergency disposition. Version 0.1. User-selected AI providers are OpenAI and DeepSeek; target EMRs are Aifya EMR and QAfya. No API keys or vendor sandbox contracts were supplied at kickoff.

Stack: FastAPI, SQLAlchemy 2, Alembic, PostgreSQL production and SQLite local demo; React, TypeScript, Vite frontend. All API paths start /api. UUID string identifiers; ISO 8601 UTC timestamps; facility comes from authenticated session, never trusted request fields. Backend owns authorization and validation. JSON errors contain detail. Mutations require X-CSRF-Token after login; session is an HttpOnly cookie. Frontend uses credentials: include. List endpoints return arrays initially with bounded limits.

Auth: POST /auth/login {email,password} -> {user:{id,email,display_name,role,facility_id,facility_name},csrf_token}. GET /auth/session returns same object, or 401. POST /auth/logout -> 204. Roles clinician, supervisor, admin; admin may configure users in own facility. Do not ship automatically enabled default credentials. Explicit seed command prints local demo account instructions and only creates synthetic data.

Patients: GET /patients?search=; POST /patients {external_id,given_name,family_name,date_of_birth,sex,female_pregnancy_status?,phone?,synthetic:true}; GET /patients/{id}; GET /patients/{id}/encounters. sex female/male/other/unknown. Date of birth determines age. Default clinical display uses external_id and name only when authorized. Patient object contains id, facility_id and submitted fields. External ID unique per facility. Server rejects pediatric use through encounter workflow; patient registration may be adult-only for this release.

Encounters: POST /encounters {patient_id,data:ClinicalData}; GET /encounters/{id}; PATCH /encounters/{id} {expected_version,data}; POST /encounters/{id}/assess -> Encounter with assessment. Encounter object {id,patient_id,version,status,data,assessment,created_at,updated_at}. status draft/reviewed. PATCH clears prior assessment. Optimistic locking returns 409 for stale version. Reassessment increments version and invalidates prior review. Finalized encounters are immutable in this release.

ClinicalData: systolic_bp?,diastolic_bp?,repeat_systolic_bp?,repeat_diastolic_bp?,pulse?,hba1c?,glucose?,glucose_unit: mmol/L|mg/dL,egfr?,potassium?,pregnancy_status: yes|no|unknown|not_applicable,known_hypertension: yes|no|unknown,known_diabetes: yes|no|unknown,medications:[{code,name,dose?,unit?,frequency?}],allergies:[string],symptoms:[string],adherence: taking|missed|unknown,notes:string,observed_at?,medicine_availability: available|limited|unknown. Numeric measurements nullable; never convert unknown to negative or zero. Symptoms vocabulary: chest_pain,breathlessness,neurological_deficit,confusion,seizure,severe_headache,visual_disturbance,vomiting,dehydration,foot_ulcer,hypoglycemia_symptoms. medications.code normalized lower snake case; common codes metformin,insulin,glibenclamide,gliclazide,lisinopril,enalapril,losartan,amlodipine,hydrochlorothiazide,spironolactone,ibuprofen,aspirin,atorvastatin.

Expanded fields: known_asthma/known_copd/known_ckd/known_cancer each yes|no|unknown; oxygen_saturation? (%), respiratory_rate? (/min), tobacco_use unknown|current|former|never; medications_reviewed/allergies_reviewed/symptoms_reviewed default false. Additional symptoms wheeze,hemoptysis,unexplained_weight_loss,persistent_cough,breast_lump,abnormal_bleeding. Empty lists are not assessed negatives without corresponding reviewed flags.

Assessment object {id,urgency: routine|soon|urgent|emergency,summary,recommendations:[{id,rule_id,category,severity:info|warning|critical,title,detail,evidence:[{source_id,title,url,section,version}]}],missing_data:[string],warnings:[string],model_info:{mode,provider?,model?,status},evidence_version,generated_at}. Stable recommendation IDs within assessment. Rules engine is backend/app/clinical.py exposing assess(data:dict, age:int, sex:str)->dict; backend supplies UUID assessment ID/time. Evidence in backend/app/evidence.py. AI enhancement cannot remove/downgrade rules or invent clinical recommendations. No automatic prescriptions; escalation and checks are advisory and require clinician review.

Review: POST /encounters/{id}/review {assessment_id,expected_version,decisions:[{recommendation_id,action:accept|modify|defer|reject,reason?,modified_text?}],note?} -> Encounter. Require decisions for every current recommendation, reasons for non-accept actions and modified_text for modify. Record clinician identity/time and immutable assessment/input snapshot. Do not label acceptance as appropriateness or safety.

Referrals: POST /encounters/{id}/referrals {reason,destination,urgency}; GET /referrals; PATCH /referrals/{id} {status:accepted|completed|cancelled,outcome?}. Object {id,encounter_id,patient_id,destination,reason,urgency,status,created_at,outcome}. Initial requested. Completed needs outcome. Strict transitions, role and facility scope. GET /dashboard -> {patients,encounters,reviewed,open_referrals,urgent_assessments}; no unsupported clinical efficacy metrics.

Audit: GET /audit (supervisor/admin) -> bounded array {id,action,entity_type,entity_id,actor_id,created_at,chain_hash}. Do not expose raw clinical notes/tokens in audit display. Audit records on patient create, encounter create/update/assess/review, referrals, login/logout, export. Backend provides atomic writes and hash-linked integrity verification where practical.

Interop: GET /fhir/Patient/{id}; GET /fhir/Bundle/{encounter_id} returns a valid R4 collection of Patient, Encounter and Observations with standard units/codes and reviewed clinical summary where available. Export only in own facility; FHIR is a tested export contract, not a claim of live Kenya HIE integration/certification. Full bidirectional adapters and national profile conformance are tracked separately if no sandbox exists.

Public GET /health/live and /health/ready. Readiness checks database and configured evidence. Production refuses insecure configuration (SQLite, weak secret, insecure cookies, enabled demo seed). Local workflow starts on 127.0.0.1, frontend proxy /api to backend. No remote patient data or secrets committed.

At least 50 independently described synthetic cases must exercise full API workflows from patient creation through assessment and reviewed records; browser workflows supplement these. Report test counts and limits honestly. No invented clinician approvals or performance rankings.
