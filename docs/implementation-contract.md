# NCDAI 2.0 implementation contract

Version 0.1, reconciled with backend/app/main.py, schemas.py, ai.py, db.py and interop.py on 12 September 2026. These files are the executable authority; the blueprint also describes future requirements. The implemented scope is standalone, clinician-supervised adult NCD support across cardiovascular/hypertension, diabetes, respiratory, kidney, cancer warning/referral and multimorbidity workflows. Synthetic records only, ages 18–120. No autonomous diagnosis, prescribing or emergency disposition. DeepSeek is the user's first AI provider; OpenAI is optional. Aifya EMR and QAfya integration is deferred until their APIs are supplied.

Stack: FastAPI, SQLAlchemy 2, Alembic, PostgreSQL production and SQLite local demo; React, TypeScript, Vite frontend. Paths below are relative to /api. UUID string identifiers; ISO 8601 UTC record timestamps and YYYY-MM-DD dates. Observation timestamps must include a timezone and retain the supplied offset when serialized. Facility comes from the authenticated session. Missing and other-facility records both return404. JSON errors contain detail (string or sanitized validation items); request objects reject unknown fields. Principal outcomes: 401 authentication, 403 role/CSRF/origin, 409 conflict/stale/immutable state, 422 validation, 429 login throttle, 503 database/readiness. Mutations after login require X-CSRF-Token. Cookie ncdai_session is HttpOnly, SameSite=Strict, path /api, Secure in production; frontend uses credentials: include. A supplied mutation Origin must match configured NCDAI_PUBLIC_ORIGIN, or request base origin if unset. No cross-origin CORS allowance. List endpoints return bounded arrays without cursor pagination.

Auth: POST /auth/login {email,password} -> {user:{id,email,display_name,role,facility_id,facility_name},csrf_token}. GET /auth/session returns the same object or401. POST /auth/logout ->204 and revokes that session. Login replaces the browser's presented session; attempt limits over ten minutes are 10 per account/source pair, 30 per account, 100 per source; 429 includes Retry-After:600. Roles: clinician and supervisor can read/write clinical records and export; admin cannot access patient/encounter/referral clinical reads merely by holding admin. Supervisor/admin can read audit; all authenticated roles can read aggregate dashboard. Only admin can GET /users (up to200 facility users) and POST /users {email,display_name,role,password} ->201 user. Password creation requires14–256 characters; facility comes from admin session. User creation can grant clinical roles and must be institutionally governed. No public signup, default credential or user edit/deactivation/password-reset API. Local seeding/provisioning is explicit; production demo seeding is disabled.

Patients: GET /patients?search=&limit=100 searches external ID/given/family name, search max100 characters, limit1–200; POST /patients {external_id,given_name,family_name,date_of_birth,sex,female_pregnancy_status?,phone?,synthetic:true} ->201; GET /patients/{id}; GET /patients/{id}/encounters?limit=100 (newest first, limit1–200). sex female/male/other/unknown. Registration enforces DOB age18–120 and an actual boolean synthetic:true. Patient response contains id,facility_id,external_id,given_name,family_name,date_of_birth,sex,female_pregnancy_status,phone,synthetic. External ID is unique per facility, max80 characters, matching [A-Za-z0-9][A-Za-z0-9._/-]*. Names max100 each, phone max40. Registration pregnancy is retained separately from the current encounter pregnancy field. No patient update/delete API.

Encounters: POST /encounters {patient_id,data:ClinicalData} ->201 version1 draft; GET /encounters/{id}; PATCH /encounters/{id} {expected_version,data} replaces the entire data object, clears assessment/review and increments version. POST /encounters/{id}/assess takes no body/client version; it assesses the persisted draft, uses the version read by the server for atomic update, replaces assessment, clears review and increments version. Save changed input first, then use the returned version. Encounter object {id,patient_id,version,status,data,assessment,review,created_at,updated_at}; assessment/review nullable; status draft/reviewed. Stale updates return409. Reviewed encounters reject PATCH, reassessment, briefing and repeat review. The backend calculates adult age from DOB using its current date at creation/assessment; a separate historical encounter-age model is not implemented.

ClinicalData: systolic_bp?,diastolic_bp?,repeat_systolic_bp?,repeat_diastolic_bp?,pulse?,hba1c?,glucose?,glucose_unit: mmol/L|mg/dL (default mmol/L),egfr?,potassium?,pregnancy_status: yes|no|unknown|not_applicable,known_hypertension: yes|no|unknown,known_diabetes: yes|no|unknown,medications:[{code,name,dose?,unit?,frequency?}],allergies:[string],symptoms:[string],adherence: taking|missed|unknown,notes:string,observed_at?,medicine_availability: available|limited|unknown. Numeric measurements default null; JSON numbers only, no strings/booleans/nonfinite values. BP supported bounds: systolic40–300, diastolic20–200 mmHg; systolic must exceed diastolic if both supplied, incomplete pairs allowed and flagged clinically. Pulse20–250; HbA1c2–25%; glucose>0 and ≤1500mg/dL or ≤83.3mmol/L; eGFR0–200; potassium1–10mmol/L. These are validation bounds, not normal ranges or dose checks.

Symptoms vocabulary: chest_pain,breathlessness,neurological_deficit,confusion,seizure,severe_headache,visual_disturbance,vomiting,dehydration,foot_ulcer,hypoglycemia_symptoms, plus expanded symptoms below; up to18 unique entries. Medications max50; code matches [a-z][a-z0-9_]*, max80, name max160; optional numeric dose>0 and ≤100000, unit max40, frequency max80. Allergies max50 nonblank strings of1–160characters. Notes default empty/max10000 and are not interpreted by rules or sent to AI. observed_at requires timezone and may be at most5minutes in the future; older values remain stored with clinical freshness warnings. Pregnancy/history/adherence/availability default unknown; lists default empty.

Expanded fields: known_asthma/known_copd/known_ckd/known_cancer each yes|no|unknown, default unknown; oxygen_saturation?30–100%, respiratory_rate?4–80/min, tobacco_use unknown|current|former|never (default unknown); medications_reviewed/allergies_reviewed/symptoms_reviewed are strict booleans default false. Additional symptoms wheeze,hemoptysis,unexplained_weight_loss,persistent_cough,breast_lump,abnormal_bleeding. Empty lists are not assessed negatives without corresponding reviewed flags.

Assessment object {id,urgency:routine|soon|urgent|emergency,summary,recommendations:[{id,rule_id,category,severity:info|warning|critical,title,detail,evidence:[{source_id,title,url,section,version}]}],missing_data:[string],warnings:[string],model_info:{mode,status},evidence_version,rules_version,generated_at,ai_briefing?}. Recommendation id equals its stable rule_id within an assessment. model_info describes deterministic mode/proposed-review status; rules_version and evidence_version separately identify implementation/evidence. backend/app/clinical.py exposes assess(data:dict,age:int,sex:str)->dict; backend supplies assessment UUID/time. Sources are in backend/app/evidence.py. No automatic prescribing or diagnostic/discharge clearance.

AI briefing: POST /encounters/{id}/ai-briefing {assessment_id,expected_version} ->Encounter; requires current assessed draft. Backend releases its transaction while provider runs, then rechecks session/clinical role/facility, assessment ID and expected version. Save increments encounter version, including stored disabled/unavailable outcomes; client must use returned version before review. Concurrent edits/reassessment/finalization return409. assessment.ai_briefing is {status:ready|unavailable|disabled|blocked,reason_code,provider,model,prompt_version,assessment_id,evidence_version,urgency,focus,checklist,source_ids,usage,latency_ms,generated_at,disclaimer}. focus contains canonical recommendation objects; checklist contains known missing-data IDs; usage is null or {input_tokens,output_tokens,total_tokens} with nullable counts. Failures expose bounded reason codes, not raw provider responses.

External AI input is only deterministic urgency, eligible {rule_id,category,severity}, locked critical rule IDs and missing-data IDs. The model returns focus_rule_ids (max3) and checklist_ids (max4), with no clinical prose. Server checks reference/schema/model integrity, uniqueness and nonempty actionable selection, then renders its own canonical text/sources. All critical findings and the complete original recommendation list remain preserved. No documents, clinical notes, numerical measurements, demographics, names or patient/encounter IDs are sent. This is bounded selection of established actions, not free-form evidence synthesis. Provider failure leaves deterministic support available.

Review: POST /encounters/{id}/review {assessment_id,expected_version,decisions:[{recommendation_id,action:accept|modify|defer|reject,reason?,modified_text?}],note?} ->Encounter, reviewed with version incremented. Exactly one decision for every current recommendation; missing/extra/duplicate decisions return422. Nonaccept actions require reason(max2000); modify requires modified_text(max4000); note max4000. review snapshot is {reviewer_id,reviewer_name,reviewed_at,assessment_id,input_version,input_snapshot,assessment_snapshot,decisions,note}. input_version is pre-review version; assessment_snapshot includes any stored briefing. Acceptance is a clinician decision, not an appropriateness/safety label.

Referrals: POST /encounters/{id}/referrals {reason,destination,urgency} ->201, allowed for draft or reviewed encounter; reason3–4000characters, destination2–200. GET /referrals?limit=100 (newest first, limit1–200). Object {id,encounter_id,patient_id,patient_external_id,patient_name,destination,reason,urgency,status,created_at,outcome}; patient labels are facility-scoped and nullable if unavailable. PATCH /referrals/{id} {status:accepted|completed|cancelled,outcome?} allows requested→accepted|cancelled and accepted→completed|cancelled; completed/cancelled terminal. Completion needs outcome(max4000); stale/invalid transitions409. Referrals do not change encounter version or send external messages. GET /dashboard ->{patients,encounters,reviewed,open_referrals,urgent_assessments}; open=requested/accepted, urgent=persisted urgent/emergency assessments; all counts facility-scoped and not clinical efficacy metrics.

Audit: GET /audit?limit=100 (supervisor/admin, limit1–200, newest first) ->array {id,action,entity_type,entity_id,actor_id,created_at,chain_hash}. GET /audit/verify ->{valid,events,head_hash,limitation} checks the facility's full retained chain; external anchoring is needed against full-history rewrite/tail deletion. Atomic audit writes cover successful login/logout, user/patient creation, encounter create/update/assess/ai_briefing/review, referrals and exports. Ordinary reads are not universally audited. Audit entries omit raw clinical notes/tokens.

Interop: GET /fhir/Patient/{id}; GET /fhir/Bundle/{encounter_id}, both clinical-role/facility-scoped, return application/fhir+json and append an export audit event. R4 collection includes Patient, Encounter, available Observations and a DocumentReference for reviewed decisions; final exports use immutable review snapshots. Missing observation time is not replaced with record creation time. Glucose preserves recorded unit with corresponding LOINC; eGFR uses a local unspecified-method code. Illustrative identity URIs do not advertise a live FHIR server. No import, SMART launch, CDS Hooks, Kenya HIE connection or Aifya/QAfya adapter is implemented; national-profile conformance and authenticated exchange require separate verification.

Public GET /health/live ->{status:live,version:0.1.0,synthetic_only:true}. GET /health/ready checks a database query, loaded rules, evidence.is_ready() and, unless test/local auto-create is enabled, exact Alembic revision20260912_guards (SCHEMA_REVISION). Success ->{status:ready,database:connected,rules:loaded,synthetic_only:true}; failure503 Database, migration or clinical evidence unavailable. Revision is checked internally, not returned. Readiness does not establish clinical approval or AI availability. Production refuses SQLite, absent/weak explicit NCDAI_SECRET_KEY, insecure cookies, demo seed, automatic schema creation or missing HTTPS NCDAI_PUBLIC_ORIGIN. Migrations run separately. /api/docs and /api/openapi.json are exposed outside production only. Local frontend proxies same-origin /api. All environments remain synthetic-only; disabling that gate is unsupported. No patient data or secrets are committed.

At least 50 independently described synthetic cases must exercise full API workflows from patient creation through assessment and reviewed records; browser workflows supplement these. Report test counts and limits honestly. No invented clinician approvals or performance rankings.
